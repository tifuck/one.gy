# ONE.GY Desktop app (Electron)

A desktop window for one.gy: the app's own title bar (drag area, back /
forward / reload, title, native window controls), its own sign-in and lock
screens, and below that the website in its desktop shell (a vertical rail
instead of the website nav, no public pages), whose "Sync" entry opens the
native sync panel next to the rail. Contract: `../docs/site-bridge.md`. Syncing itself happens in the Go engine
(`../engine`); the app talks to it over the socket/pipe described in
`../docs/engine-ipc.md`. No native Node modules.

## Run

```bash
npm ci
npm run vendor       # copy the website's CSS + fonts from ../../static into src/ui/site/
                     # (also runs before start, dev:mock and dist; CI runs it too)
npm run dev:mock     # against dev/mock-engine.js (seeded syncs, transfers, issues)
npm run build:engine && npm start   # against the real engine (needs Go)
npm test             # unit tests: settings, notifications, shortcuts, tray menu + popover placement,
                     # sync/bridge status, site paths + rail width, JSON-RPC + supervisor vs the mock
```

Dev-only flags (ignored in packaged builds): `--mock-engine`, `--server=https://…`
(sets the server URL; only https is accepted). F12 opens DevTools in dev.
Packaged builds start on `https://one.gy`; Settings > General > Server in the
sync panel changes it.

Keys (the title bar has back / forward / reload too): Alt+←/→ and the mouse
back/forward buttons, Ctrl+R / F5, Ctrl+Shift+R, Ctrl+= / Ctrl+- / Ctrl+0 (zoom, kept),
Ctrl+Shift+S (sync panel, once this computer is authorized), Esc closes the
panel.

To work on the panel in a plain browser, serve this folder and load
`dev/mock-core.js` + `dev/ui-stub.js` before `src/ui/index.html` (they stand
in for the preload and the site's `openSync`; hash flags in `ui-stub.js`,
`#signed-out,user=` for the app's sign-in; `src/ui/popover.html` works the
same way). The panel uses the website's real stylesheets
(`src/ui/site/`, generated by `npm run vendor`, gitignored), so it looks
exactly like the site; `styles/app.css` only adds panel-specific bits.

End to end without a display: `dev/browser-bridge.js` serves `src/ui` on
127.0.0.1 and proxies `window.onegy` (`dev/bridge-client.js`) to a real
engine it supervises; `POST /panel` stands in for the site's `openSync` and
`GET /site-status` for `onStatus`. `test/e2e_bridge.py` drives the real panel
through it with Playwright against a DEV server (signed out = no sync UI,
setup for the website user, wizard, sync both ways, engine restart, conflict,
backup, pause, remove, other-account guard; screenshots). See the header of
that script; it only runs with `ONEGY_E2E=1`. `dev/` and `test/` are never
packaged.

## Package

```bash
npm run dist                          # engine + installers for this OS into dist/
node scripts/dist.js --linux deb rpm  # some Linux targets (rpm needs rpmbuild)
```

The version comes from `../VERSION` (`package.json` keeps `0.0.0-dev`).
`scripts/dist.js` builds each Linux target in its own electron-builder run and
merges their `*-linux.yml` (see `electron-builder.yml` for why). Release builds
run in `.github/workflows/desktop-release.yml`:

- Windows: `ONE.GY-Desktop-Setup.exe` (NSIS)
- Ubuntu / Debian / Mint: `onegy-desktop_amd64.deb`
- Fedora / openSUSE / RHEL: `onegy-desktop.x86_64.rpm`
- portable Linux: `ONE.GY-Desktop-x86_64.AppImage`

plus `latest*.yml` / `beta*.yml` for auto-update. The deb and rpm install to
`/opt/ONE.GY Desktop` with a desktop entry and icons. Builds are unsigned for
now. Icons: `npm run icons` regenerates `build/`, `src/assets/` and the site
favicons in `static/logos/` from `scripts/make-icons.js`.

## Structure

```
src/main/       main process
  main.js         lifecycle, single instance, autostart, close-to-tray, power-save,
                  site bridge status push, quit
  window.js       BaseWindow (hidden title bar + native controls overlay): title bar
                  view, site view (persist:onegy, User-Agent token for the desktop
                  shell) and sync panel view (right of the site's rail); shortcuts,
                  zoom, offline page
  shortcuts.js    key -> action, zoom steps
  sync-status.js  account + engine status + issues -> tray and onStatus states
  protocol.js     app:// scheme serving src/ui with a strict CSP
  security.js     web preferences, navigation locks, permissions, TLS, downloads
  engine.js       engine supervisor (connect, spawn, restart with backoff)
  rpc.js          JSON-RPC 2.0 client, newline framing
  ipc.js          ipcMain handlers: engine method whitelist + app actions + site bridge
  ui-methods.js   the engine methods the native panel may call
  site-nav.js     validates site paths and the rail width the site preload reports
  environment.js  battery (powerMonitor) and metered network -> engine.environment
  remove-sync.js  remove a sync; optionally move its folder to the system trash
  tray.js         tray icon and menu; left click opens the tray popover
  tray-popover.js the popover window by the tray icon (placement, hide on blur, actions)
  notify.js, updater.js, settings-store.js
src/preload/    app-preload (panel bridge), titlebar-preload, update-preload, popover-preload, site-preload
                (window.onegyDesktop, bridge 2; theme, rail width, panel state,
                sign-out handed to the app)
src/ui/         native panel, plain ES modules, no build step
  app.js          panel shell: admin console layout (sidebar + page), gating
                  (sign-in / setup / lock / other account / sections), router
  titlebar.html   the window's title bar (titlebar.js, styles/titlebar.css)
  update.html     the update toast (update.js, styles/update.css)
  popover.html    the tray popover (popover.js, styles/popover.css): state, storage,
                  syncs, transfers, issues; read-only, actions go to main
  store.js        state fed by engine events + bridge wrappers
  screens/        signin, wizard (incl. setup and onboarding), lock, syncs,
                  transfers, issues, settings
  components/     dialog, menu, toast, tree picker, sync options, "What to sync"
                  (sync-filter.js on rules.js: .onegyignore as ticks and filters), formatting
  offline.html    "Can't reach <server>" page for the site view
  site/           generated: the website's CSS + fonts (scripts/vendor-site.js)
  styles/app.css  panel-only additions, site tokens and classes
dev/            mock engine, browser stub, browser bridge to the real engine
scripts/        vendor-site, build-engine, dist, make-icons
test/           node --test, plus the env-gated e2e_bridge.py
```

## Notes

- Updates ask before they restart (`updater.js`). The app checks every 30
  minutes, on resume and on relaunch (Settings > General > Check for updates
  any time); the update toast (`ui/update.html`, a view in the window's bottom
  right corner) offers Update and restart / Restart now. The restart writes
  `relaunch-state.json` (window bounds, maximized, hidden, site page, open
  panel screen) and the next start opens there; with the app lock on, the lock
  screen comes first. A ready update restarts by itself only while the window
  is hidden in the tray or minimized and not mid-sync. NSIS and AppImage:
  electron-updater (generic provider on this repo's latest GitHub release)
  downloads in the background, Restart now installs silently and relaunches.
  The beta channel reads `beta*.yml`, which every release also carries. deb and
  rpm (told apart by `resources/package-type`): the package's post-install
  script (`build/linux/after-install.sh`, the builder's default plus our block)
  installs a root systemd timer `onegy-desktop-update.timer` that runs
  `resources/update-system.sh` every 30 minutes: it installs the latest stable
  release after checking its sha512 from `latest-linux.yml`. The app reads
  `latest-linux.yml` itself; Update and restart runs `systemctl start
  onegy-desktop-update.service`, which a polkit rule
  (`/etc/polkit-1/rules.d/49-onegy-desktop-update.rules`) allows for the local
  active user without a password (older polkit asks for it). When the timer
  installs first, the app notices `app.asar` was replaced and asks to restart.
  deb and rpm follow the stable channel only.
- The website bridge (`window.onegyDesktop`: `unlock`, `openSync`, `onStatus`)
  exists only on top-level frames of the configured server; the main process
  re-checks the frame for every call and the engine's `web_unlock` setting
  decides about the key.
- After a POST/PUT/PATCH/DELETE to the server from the site view, the app asks
  the engine to poll (`engine.nudge`).
